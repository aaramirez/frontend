Curso visual e interactivo · Desarrollo de software

De la idea a la interfaz que se usa todos los días

Una aplicación de frontend no es una página con JavaScript: es un árbol de componentes, un estado que cambia, datos que llegan de una API y una persona que la usa con el ratón, el teclado o un lector de pantalla. Este curso enseña a construirla con las herramientas de hoy, con laboratorios donde ves cada render, cada petición y cada métrica.

Cómo usar este curso

Estado. El curso está en preparación. La tabla de contenido ya tiene los 13 capítulos con sus secciones y sus laboratorios, y está en revisión.

Para quién es. Para quien ya escribe HTML, CSS y JavaScript y quiere construir aplicaciones completas. Conviene haber visto Páginas web y JavaScript; la historia y el origen de los patrones de los frameworks están en Aplicaciones web, y los tipos en TypeScript.

Cómo está hecho. Un mismo proyecto recorre el curso: un panel de pedidos de una tienda que lista, filtra, crea y sigue pedidos contra una API REST con los lineamientos de referencia. Se construye en React y se compara en Angular, Vue y Svelte. Los laboratorios muestran los renders, el estado, las peticiones y las métricas mientras cambias el código.

Cada capítulo con sus secciones y sus laboratorios.

Parte 1 Herramientas y componentes
01El frontend moderno y su cadena de herramientas

Del código que escribes al que descarga el navegador: transpilar, empaquetar, minificar y servir en desarrollo.

02Componentes: props, composición y ciclo de vida

La interfaz como un árbol de piezas que reciben datos, se combinan y se vuelven a dibujar cuando algo cambia.

03React a fondo: hooks, efectos y contexto

`useState`, `useEffect`, `useMemo` y `useContext`, cuándo se vuelve a dibujar un componente y cómo evitarlo.

Parte 2 Estado y datos
04Estado: local, global y del servidor

Tres clases de estado que piden herramientas distintas: Redux, Zustand, TanStack Query y máquinas de estado.

05Consumir APIs REST con los lineamientos de referencia

El sobre de respuesta, los errores con `traceId`, la paginación, la idempotencia y los avisos por SSE, del lado del cliente.

06Formularios y validación

Controlados o no, validación en el cliente y en el servidor, y esquemas compartidos.

Parte 3 Otros frameworks y estilos
07Angular, Vue y Svelte comparados

El mismo componente en cuatro frameworks, con su forma de manejar plantillas, estado y reactividad.

08Estilos y sistemas de diseño

CSS Modules, Tailwind, CSS-in-JS y tokens de diseño: cómo mantener una aplicación grande coherente.

Parte 4 Calidad y arquitectura
09Accesibilidad de aplicaciones

ARIA, foco, teclado y lectores de pantalla en componentes interactivos: menús, diálogos y avisos.

10Rendimiento: Core Web Vitals

LCP, INP y CLS, y las técnicas para mejorarlos: dividir el código, cargar después, optimizar imágenes.

11Pruebas de interfaz

Testing Library para componentes, Playwright de punta a punta y servidores simulados con MSW.

12Patrones y arquitectura del frontend

Contenedor y presentación, hooks propios, máquinas de estado, arquitectura por funcionalidades y micro frontends.

13Prompts para generar un frontend de producción

Qué pedirle a un asistente para que los componentes que genera manejen sus estados, sean accesibles, rápidos y estén probados.
